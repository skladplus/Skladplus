# 02 — Решения

Единый журнал: решение · обоснование · дата. Отвергнутые варианты записаны вместе
с принятыми — иначе через месяц их начнут пересматривать по кругу.
ADR отдельными файлами не ведём: при двух разработчиках один список читается быстрее.

## Продукт и организация работы

| Решение | Обоснование | Дата |
|---|---|---|
| Свой код на Next.js + Postgres, не low-code | Lovable и Base44 не дают контроля над мультиклиентским разграничением доступа и биллингом; переписывать пришлось бы целиком | 2026-08-22 |
| Этап 0 — только каркас, без схемы БД и UX | Бизнес-правила не закрыты, часть ответов есть только у заказчика; написанная сейчас схема была бы переписана. Репозиторий, процесс и защита от этих ответов не зависят | 2026-08-22 |
| Организация `skladplus`, оба владельца | Личный репозиторий одного человека — единая точка отказа и неравные права при заявленном паритете 50/50 | 2026-08-22 |
| Репозиторий публичный | CodeRabbit, защита веток, CODEOWNERS и минуты Actions на публичном репозитории бесплатны. Код защите не подлежит — защищаем секреты, доступы и данные | 2026-08-22 |
| Free-организация, не Team | На публичных репозиториях Team не даёт ничего сверх Free | 2026-08-22 |
| Файла `LICENSE` нет | Отсутствие лицензии = все права защищены. Открытый исходный код не означает разрешения на использование | 2026-08-22 |
| Тарифы заказчика публикуем с числами | Приняли осознанно: условия видны конкурентам, ответ на вопрос заказчика готовим заранее | 2026-08-22 |

## Процесс

| Решение | Обоснование | Дата |
|---|---|---|
| Апрув второго человека на merge не обязателен | Двое, работают параллельно; обязательный апрув превратился бы в очередь. Гейт — зелёный `ci-ok` и CodeRabbit | 2026-08-22 |
| Прямой push в `main` закрыт для всех, `bypass_actors: []` | Исключение для владельца обесценивает защиту: обходить будут в спешке, а спешка и есть источник сломанного `main` | 2026-08-22 |
| Только squash-merge | Линейная история; merge-коммиты и rebase отключены на уровне репозитория, а не договорённости | 2026-08-22 |
| `squash_merge_commit_message = BLANK` | При PR из одного коммита GitHub предзаполняет тело PR телом коммита — запрещённый AI-трейлер вернулся бы этим путём | 2026-08-22 |
| `strict_required_status_checks_policy: false` | При двух параллельных писателях strict сериализует мержи: каждый чужой merge сбрасывает готовность второго. Вместо него `allow_auto_merge` | 2026-08-22 |
| Один обязательный чек — агрегат `ci-ok` | Иначе новый job не станет обязательным автоматически, а переименование старого молча откроет мерж | 2026-08-22 |
| `paths:` и `paths-ignore:` в CI запрещены | Отфильтрованный обязательный чек навсегда остаётся `pending` и блокирует PR | 2026-08-22 |
| Отвергнут commitlint | Conventional Commits соблюдаются двумя людьми без робота; ещё один красный чек не окупается | 2026-08-22 |
| AI в авторстве запрещён | Требование заказчика работ: контрибьюторы — только люди. Механизм: `includeCoAuthoredBy: false` + правило в `AGENTS.md` для Codex + job `authorship` как страховка. `git config` этим не управляет — трейлер добавляет агент, а не git | 2026-08-22 |
| Каркас делает один человек, не оба | День-полтора работы; координация двоих съела бы больше, чем сэкономила | 2026-08-22 |
| После каркаса — trunk-based, ветки на часы, stacked PR, флаги, worktrees | Узкое место при работе с агентами — не написание кода, а ревью и интеграция. Выигрыш даёт сокращение времени жизни ветки, а не рост их числа | 2026-08-22 |
| Домен делится по ограниченным контекстам | Товары/поставки/остатки одному, заказы/отправки/возвраты другому, каждый от таблицы до экрана. Деление по слоям заставляло бы ждать друг друга | 2026-08-22 |

## Инструменты

| Решение | Обоснование | Дата |
|---|---|---|
| Biome вместо ESLint + Prettier | Один конфиг вместо двух, нет конфликта форматтера с линтером, оба IDE форматируют одинаково | 2026-08-22 |
| TypeScript 7.0.2 (нативный компилятор) | Уже `latest`, не rc; `tsc --noEmit` проверен на скелете. При проблеме откат на 5.9 — одна строка | 2026-08-22 |
| pnpm 10.34.5, не 11 | 11 вышел недавно; выгоды нет, а Vercel corepack и `pnpm/action-setup` на 10 проверены | 2026-08-22 |
| `packageManager` + corepack, версия пинуется точно | `pnpm/action-setup` без поля `version` берёт её отсюда; указание версии в двух местах даёт конфликт | 2026-08-22 |
| Все скрипты корня — `pnpm -r --if-present` | CI зелёный на пустом монорепо и остаётся зелёным по мере появления пакетов. Без этого CI не мог бы позеленеть до появления приложения, а приложение не могло бы появиться до зелёного CI | 2026-08-22 |
| CI ставит зависимости с `--ignore-scripts` | От карантина на свежие релизы отказались, поэтому это единственный барьер против вредоносного `postinstall` на раннере с токенами. Нужные сборки вызываются явными шагами | 2026-08-22 |
| `pnpm dlx` и `npx` запрещены | Резолвят latest на каждом прогоне: невоспроизводимая сборка и открытый вход для supply-chain | 2026-08-22 |
| gitleaks бинарём, не экшеном | Экшен требует лицензию для организаций | 2026-08-22 |
| Отвергнут gitleaks в pre-commit | Обходится `--no-verify`; реально гарантирует только серверный push protection, который включён | 2026-08-22 |
| Отвергнут Redis в docker-compose | Воркера ещё нет; сервис без потребителя только ломает старт | 2026-08-22 |
| Vercel + Neon, не свой сервер | Двое разработчиков; администрирование сервера — третья работа, которой нет | 2026-08-22 |
| Каркас обязан работать на локальном Postgres без Vercel и Neon | Иначе второй разработчик заблокирован чужими доступами | 2026-08-22 |
| Neon: отдельный проект, не общий с NovaPostBot | Общая база двух продуктов разных клиентов — ошибка разграничения доступов и бэкапов | 2026-08-22 |
| Миграции отдельным джобом на `push: main`, не внутри `next build` | Сборка Vercel параллельна и кэшируется — получились бы две миграции на одной базе. Джоб с `concurrency: deploy-main` | 2026-08-22 |
| Neon MCP видит только ветку с синтетикой | Прод-данные не должны попадать в контекст агента ни при каком стечении обстоятельств | 2026-08-22 |

## Код

| Решение | Обоснование | Дата |
|---|---|---|
| Деньги — целые копейки, `bigint` | Prisma по умолчанию даст `Float`, и это проскочит незамеченным до первого расхождения в счёте. `Decimal.js` не сериализуется через границу server/client в Next.js | 2026-08-22 |
| Время — `timestamptz`, вывод через `Intl.DateTimeFormat('uk-UA', {timeZone:'Europe/Kyiv'})` | Рантайм Vercel — UTC, переопределить `TZ` там нельзя. Иначе локальная машина в киевской зоне даст зелёные тесты при красном проде, и всплывёт это на SLA «30 рабочих минут» | 2026-08-22 |
| Доступ к данным — обёртка-репозиторий с обязательным `accountId` | Доступ к чужим заказам — риск номер один в мультиклиентской системе. Закладывается пока каркас пуст: час работы сейчас против унификации разъехавшихся реализаций потом. Слабое место честное — обходится прямым вызовом Prisma; дисциплину держит линтер и то, что доступ живёт в одном месте | 2026-08-22 |
| Интерфейс украинский, комментарии и документы русские | Как в NovaPostBot | 2026-08-22 |
| `packages/core` не импортирует React и Next | Иначе бизнес-логика прирастает к фреймворку и не тестируется отдельно | 2026-08-22 |

## Память и правила

| Решение | Обоснование | Дата |
|---|---|---|
| `AGENTS.md` — канон, `CLAUDE.md` — указатель | Codex читает только `AGENTS.md`; правило, попавшее лишь в `CLAUDE.md`, для второго разработчика не существует | 2026-08-22 |
| Лимит `AGENTS.md` — 150 строк, проверяется в CI | Длинный файл работает хуже короткого: середина теряется. Детали выносятся в `docs/` со ссылкой | 2026-08-22 |
| Единственная общая память двух агентов — файлы в репозитории | Персональная память Claude не лежит в git и второму недоступна | 2026-08-22 |
| `scripts/context.sh` — один ввод в контекст для обоих | У Claude висит на `SessionStart`, у Codex вызывается по правилу «шаг 0». Один источник, никакого дублирования | 2026-08-22 |
| Журналы раздельные: `PROGRESS/alex.md` и `PROGRESS/step.md` | Общий файл давал бы конфликт в каждом PR | 2026-08-22 |

## Принятые риски

Это решения, а не упущения.

1. **Автодеплой из `main` без человеческого гейта.** Зелёный CI не защищает от автора, который пишет и код, и тесты. Страховка — CodeRabbit и откат за 30 минут.
2. **PR, правящий `.github/`, проверяется уже изменённым workflow** — гейт проверяет сам себя. Реализуется только при компрометации аккаунта одного из двоих.
3. **Bus factor за пределами организации не закрыт:** нет офлайн recovery-кодов, второго админа в Neon, Vercel и Sentry, зеркала репозитория. Два владельца организации закрывают главный сценарий, остальные остаются.
4. **Без карантина на свежие npm-релизы.** Барьер — только `--ignore-scripts` в CI.
5. **Публичный репозиторий с тарифами заказчика.**
6. **Deny-правила агентов — не граница, а трение.** Запрет `curl` обходится через `node -e`; запрет чтения `.env` — через `cat` и `grep -r`. Реально работает вынос секретов за пределы рабочей папки, всё остальное лишь удорожает случайную ошибку.
