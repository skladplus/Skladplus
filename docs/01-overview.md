# 01 — Обзор продукта и текстовая карта разделов

## Назначение

Skladplus — веб-платформа фулфилмента для склада в Харьковской области. Она
заменяет связку «Google-таблица + чат + Telegram-бот» единым кабинетом для
приёмки, адресного хранения, сборки, отправки, возвратов и расчётов.

Документ описывает продуктовый контур и предварительную навигацию. Это не
контракт API, схемы БД или окончательная спецификация экранов. Незакрытые
бизнес-вопросы перечислены в `docs/findings-backlog.md`.

## Участники и границы доступа

| Участник | Основная задача |
|---|---|
| Владелец склада | Управляет клиентами, тарифами, складом, документами и финансовым обзором |
| Менеджер склада | Обрабатывает поставки, заказы, сборку, отправки, возвраты и расхождения |
| Работник склада | Выполняет назначенные операции на складе без доступа к биллингу и настройкам клиентов |
| Клиент — магазин | Передаёт поставки и заказы, смотрит остатки, отправки, документы и счета |
| Сотрудник команды клиента | Работает в кабинете клиента в пределах выданных прав |
| Разработчик | Техническая роль проекта; не является обычным пунктом пользовательской навигации |

Граница данных проходит по `account`: любой запрос к данным клиента должен быть
ограничен его `accountId`. Термины предметной области: `order` — заказ,
`shipment` — отправление и ТТН, `supply` — поставка, `stock` — остаток,
`item` — позиция товара.

## Видимость разделов по ролям

Это предварительная матрица верхнего уровня. Детальные действия внутри
разделов должны быть проверены через роли и `accountId`, а не только скрытием
пункта меню.

| Раздел | Владелец склада | Менеджер | Работник | Клиент | Команда клиента |
|---|:---:|:---:|:---:|:---:|:---:|
| Главная | ✓ | ✓ | ✓ | ✓ | ✓ |
| Заказы и отправления | ✓ | ✓ | по задаче | ✓ | по праву |
| Возвраты | ✓ | ✓ | по задаче | ✓ | по праву |
| Товары, остатки и поставки | ✓ | ✓ | по задаче | ✓ | по праву |
| Склад и инвентаризация | ✓ | ✓ | по задаче | — | — |
| Документы | ✓ | ✓ | — | ✓ | по праву |
| Счета и тарифы | ✓ | по просмотру | — | ✓ | по праву |
| Команда и доступы | ✓ | по полномочию | — | ✓ | — |
| Интеграции | ✓ | по полномочию | — | ✓ | по праву |
| Настройки | ✓ | по полномочию | — | ✓ | по праву |

## Связь разделов с рабочим циклом

```text
Поставка → Приёмка → Остатки и ячейки
                         ↓
Клиентский заказ → Резерв → Сборка → Передача перевозчику → ТТН и статус
                                                               ↓
                                                            Возврат

Операции → Документы и журнал → Рахунок за период
```

Резерв остатка создаётся при приёме заказа. Один заказ связан ровно с одной
ТТН. Передача перевозчику и последующее подтверждение сканом Новой Пошты —
разные события; это важно для SLA и не должно быть сведено к одному статусу.

## Что пока не фиксируем

- точный состав статусов возврата и правила тарификации;
- видимость физического, свободного и зарезервированного остатка для клиента;
- правила комплектов, инвентаризации и частичной сборки;
- состав отчётов владельца склада и каналы уведомлений;
- окончательные названия экранов и порядок пунктов меню.

Источник открытых решений и вопросов: `docs/findings-backlog.md`.
