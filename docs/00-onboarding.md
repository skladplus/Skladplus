# 00 — Онбординг разработчика

Документ рассчитан на человека, который впервые получил доступ к репозиторию.
Он дополняет `scripts/bootstrap.sh`: скрипт поднимает локальный проект, а здесь
описаны порядок чтения, доступы, рабочие правила и действия при проблемах.

## Что прочитать сначала

1. `AGENTS.md` — обязательные правила работы.
2. `README.md` — назначение проекта и быстрый старт.
3. `docs/01-overview.md` — продукт и текстовая карта разделов.
4. `docs/02-architecture.md` — принятые технические решения.
5. `docs/findings-backlog.md` — открытые вопросы, которые нельзя додумывать.

В начале каждой сессии выполнить:

```bash
bash scripts/context.sh
```

Скрипт показывает текущую ветку, последние коммиты, незакоммиченные файлы и
контекст параллельной работы.

## Что нужно до старта

- доступ к репозиторию `skladplus/Skladplus`;
- Node.js мажорной версии из `.nvmrc`;
- Corepack и pnpm версии из поля `packageManager` в `package.json`;
- запущенный Docker Desktop с Compose;
- доступ к локальным значениям в `~/.skladplus/env`, если они уже выданы.

Настоящие секреты не запрашиваются в чате, issue или PR. В репозитории есть
только `.env.example`; файл `.env*` читать и коммитить нельзя.

## Первый запуск

Из корня клона выполнить:

```bash
bash scripts/bootstrap.sh
```

Скрипт проверит Node и Docker, создаст `~/.skladplus/env` из образца при его
отсутствии, установит зависимости, поднимет локальный PostgreSQL, применит
миграции, сгенерирует Prisma Client и запустит typecheck и тесты.

После успешного запуска:

```bash
pnpm dev
```

Проверки:

- приложение: `http://127.0.0.1:3000`;
- healthcheck: `http://127.0.0.1:3000/api/health`;
- локальная база по умолчанию слушает порт `5433`, а не `5432`.

Если порт `5433` занят, перед запуском задать другой порт и повторить bootstrap:

```bash
SKLADPLUS_DB_PORT=55433 bash scripts/bootstrap.sh
```

## Ежедневные команды

```bash
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

Для миграций и локальной базы используются команды из корневого `package.json`:

```bash
pnpm db:generate
pnpm db:deploy
pnpm db:status
```

`pnpm dlx` и `npx` запрещены: зависимости должны разрешаться из lock-файла.

## Рабочий процесс

1. Перед началом — `git fetch` и rebase своей короткой feature-ветки на
   `origin/main`, если это не конфликтует с текущей работой второго разработчика.
2. Ветка имеет формат `feat|fix|chore|test|docs/<owner>-<кратко>`, где owner —
   `alex` или `step`.
3. Изменения точечные: не добавлять в коммит чужие незакоммиченные файлы.
4. Коммит — Conventional Commits, по-русски, без `Co-Authored-By` от ИИ.
5. В PR указать, какую задачу закрывает изменение, команды проверки и отсутствие
   ПДн. Завершённую задачу отметить в соответствующем GitHub Issue.
6. В `PROGRESS/<owner>.md` добавить запись после локального коммита.

В `main` не выполняется прямой push: изменения проходят через PR и squash-merge.
Если затронуты общий контракт, CI, схема БД или `AGENTS.md`, в заголовке PR нужен
маркер `[contract]` и второй разработчик должен быть на связи.

## Если что-то не запускается

| Симптом | Что проверить |
|---|---|
| Нет Node или неверная версия | `.nvmrc`, менеджер версий Node, затем `corepack enable` |
| Docker не отвечает | Docker Desktop и `docker info` |
| Порт базы занят | `SKLADPLUS_DB_PORT`, затем перезапустить bootstrap |
| Нет подключения к базе | `docker compose ps` и `docker compose logs postgres` |
| Prisma не видит переменные | наличие `~/.skladplus/env`; `.env` в репозитории не создавать |
| Зависимости расходятся | `pnpm install --frozen-lockfile`; lock-файл руками не редактировать |
| Непонятна бизнес-логика | сначала проверить `docs/findings-backlog.md`, затем спросить владельца задачи |

Не удалять Docker volume или базу, если не проверено, что там нет нужной локальной
работы другого разработчика.
